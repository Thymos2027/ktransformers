## 只读预检结果

2026-11-10 21:40 核查：原单卡容器仍运行，物理 NPU 2、5 均为 `OK`、57°C；NPU 2 有原模型进程，NPU 5 无模型进程。`npu-smi info -t topo` 将两卡之间标为 `SYS`：通信经过 PCIe 和 NUMA/SMP 路径，未显示 HCCS 连接；卡的 CPU affinity 分别为 0–31 和 64–95。必须先测 HCCL 两卡集合通信，不能仅根据设备都可见就认定 TP 通信可用或足够快。

当前 SGLang 固定提交仍为 `ff46d660d16cbf11ef393c80cc6b3ab7f6259780`，工作区 tracked diff 为空。`python/sglang/srt/layers/moe/kt_ep_wrapper.py` 第 180–184 行在 NPU + KT 权重路径下明确拒绝 TP≠1 或 EP≠1，报错为：

```text
KT expert offload on NPU currently supports only --tensor-parallel-size 1 and --expert-parallel-size 1
```

该文件 SHA-256：`ac454c4aa5410181625a8c9aa520b7c18b6ab210e2706586e0fc7d64aad4dd8f`。现有 KT `serve.sh` 也将 TP/EP 写为 1/1。因此当前源码不能只改启动参数就获得 TP=2；本轮先做适配与正确性验证，不预设已有可用实现。

代码中已有可研究的机制：CPU 专家 wrapper 只由 TP rank 0 创建并运行，其他 rank 返回零 CPU 输出；NPU 常驻专家按中间维度分片，MoE 在 combine 后有条件执行 all-reduce。这些只提供适配起点，尚未验证两个 rank 的路由、CPU 输出求和次数、W8A8 权重/缩放分片与注意力路径。不能仅删除 TP 限制便宣称支持。

现有 W8A8 检查点为 294,635,333,768 字节，两卡共 128 GiB HBM，无法作为完整 W8A8 常驻双卡的容量方案。继续使用同一模型需保留 KT CPU 专家卸载；不擅自更换模型或量化格式。

## 目标配置与分步门槛

| 项目 | 首个候选 |
| --- | --- |
| 服务形态 | 一个 API、一个模型实例、两个 TP rank，共同处理同一请求 |
| 设备 | 容器逻辑设备 0、1，对应物理 NPU 2、5 |
| 并行参数 | `--tensor-parallel-size 2 --expert-parallel-size 1 --moe-a2a-backend none` |
| 模型与权重 | 复用现有 W8A8 + 逐层 MXFP4 GGUF，只读挂载 |
| 初始专家设置 | 每层同一组 32 个 NPU 常驻专家，在两 TP rank 间分片；先不增加专家数 |
| CPU 执行 | 保留 rank 0 唯一 CPU wrapper；核查 CPU 专家只算一次、输出只加一次 |
| 首轮上下文/请求 | 8192 token 上限、单请求；先 32–64 输出 token 的短请求 |
| 内存池总 token 上限 | 第二轮自动预算 OOM 后，第三轮增加 `--max-total-tokens 16384`；上下文仍为 8192 |
| 执行模式 | eager 正确性通过后再验证图捕获；不一次开启额外加速开关 |
| 环境 | 独立 SGLang 源码副本和独立实验容器，不改固定基线源码或权重 |

1. 在隔离副本审查并适配 TP 相关的 NPU 路由、权重分片和 CPU 输出合并；明确记录 diff。门禁仅在实际需要的配置范围放开，不把删除检查当作支持实现。
2. 临时停原单卡容器释放 NPU 2，在相同镜像与驱动下做小规模 HCCL all-reduce 正确性与超时检查。失败则停止模型试启动，保存通信错误。
3. 用两 rank 加载同一个模型，先 eager。检查日志中 TP world size/rank、两卡进程及 HBM、一个 API；通过确定性答案、SSE `[DONE]`、usage 和结束原因。可运行时补固定历史的数值/任务验证，不要求跨不同 TP 布局逐字一致来替代数值或任务验收。
4. eager 通过后单独验证图捕获与短请求重放。出现错误或超时即收尾，不在同一后台流程反复改代码重试。
5. 正确性通过后另做与单卡同请求、同专家集合的性能对照。增加常驻专家数属于后续独立变量；TP=2 不预设能把仍在 CPU 上执行的专家计算加速两倍。

## 运行保护、恢复与授权边界

此前发生过 NPU 高温及掉卡，原因未明；实际试跑沿用已验证的独立温度/风扇监控：两卡必须均可读且 `OK`、温度低于 70°C、四风扇均不低于 4500 RPM；连续两次读不到遥测也停止实验容器。以上是本实验的保守中止条件。整体设有限时和集合通信超时，后台保存阶段状态、标准输出/错误、两 rank 日志和热采样。

正常结束或软件兼容性失败时停止实验容器，在两卡与散热检查通过后恢复原单卡容器，并核对 `/health` 与短请求；若触发热保护或设备失联，则保持模型容器停止，不自动重新加载。未经新的明确授权不进行整机重启、电源或风扇策略修改。

11 月 10 日只完成了只读预检和本地方案准备。11 月 11 日用户明确同意隔离副本中的 TP=2 试跑、临时停原服务与正常结束/软件失败后的恢复；未授权新的整机电源或风扇策略修改。
