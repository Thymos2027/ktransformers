## 同步资源证据与解释

从 `snapshots.jsonl` 的 D 阶段边界相减，96+32 本轮 117 秒内 CPU PSI `some` 累计增加 **35.12 秒（30.0%）**；此前 96+96 的 122 秒窗口增加 **109.93 秒（90.1%）**。按主机 `CLK_TCK=100` 折算，两实例进程合计 CPU 时间本轮增加约 **10,708 CPU 秒**，即窗口平均 **91.5 核**；此前约 **11,188 CPU 秒 / 122 秒 = 91.7 核**。可运行任务争用指标明显下降，但 CPU 消耗与并发吞吐几乎不变。这说明**减少第二实例线程预算缓和了调度等待，却没有消除当前主要性能退化**；不能据此将线程总数超过物理核视为唯一根因，也不足以提交 32 线程默认值。

本轮 D 阶段 `pswpin` 增加 1355、`pswpout` 不变，结束时 `MemAvailable` 约 210.9 GiB；不能说完全没有换入，但没有观察到伴随并发请求的持续换出。B 阶段预热窗口曾出现大量换入和换出，且该阶段预热请求慢于正式请求；其冷加载影响不应混入 D 阶段结论。

若以后另立实验，宜在同一启动周期内对**两实例分别设定不重叠的 CPU 亲和性与 NUMA 内存放置**，同时记录逐线程实际亲和性、CPU PSI、内存带宽和端到端吞吐。第二实例仅改为 32 线程后，进程仍有 94 个线程，原实例有 158 个；配置的 CPU 推理线程数之和不是整机实际可运行线程数。这是待检验的机制假设，当前没有完成亲和性和带宽测量。本系列现已[结项](CLOSEOUT.md)，不自动开展后续双实例实验。
