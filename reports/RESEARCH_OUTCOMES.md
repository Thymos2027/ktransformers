# taishan 阶段成果与证据边界

更新：2026-11-10（北京时间）。本页汇总已产生的结果，供研究复盘和上游沟通使用；计划中的基准与优化不列为成果。当前执行状态见[研究状态](RESEARCH_STATUS.md)。

## 1. 可复现的单卡部署与短请求验收

[2026-11-04 部署报告](2026-11-04-taishan-deepseek-v4-flash/README.md)记录了双路鲲鹏 920、单张 910B4-1、KT CPU MXFP4 专家与 SGLang NPU W8A8 路径的固定提交、镜像摘要、模型来源、启动参数和验收记录。服务在单请求、8192 token 配置下完成图捕获、健康检查、结构化聊天与 SSE `[DONE]`。客户端三条短请求的耗时是功能验收观察值，不能当作 TTFT、tokens/s、稳定吞吐或模型准确率成绩。报告没有覆盖并发或长上下文。

## 2. 逐层 MXFP4 CPU 专家权重与上游文档

[社区发布记录](2026-11-04-taishan-deepseek-v4-flash/community-release/README.md)确认 43 个 GGUF 合计 147,169,763,520 字节，完成所有层、专家和投影的打包字节/缩放比较及上游 bit-exact 验证；发布文件的远端大小与 SHA-256 已核对。权重在 [ModelScope](https://modelscope.cn/models/kmon03f/DeepSeek-V4-Flash-KT-MXFP4-CPU-Experts) 提供，对应 [KT 文档 PR #2257](https://github.com/kvcache-ai/ktransformers/pull/2257) 于 2026-11-06 合并。贡献是可验证的专家权重发布、来源记录与文档入口；不声称新量化算法，也不代表 W8A8 检查点、长上下文或性能已获普遍验证。

## 3. 专家路由覆盖与搬运成本的有界证据

[2026-11-07 专家缓存研究](2026-11-07-taishan-expert-cache-study/README.md)在第二张卡的独立 SGLang 进程上采集 20 条受控请求，离线比较每层 32 个常驻专家的放置策略。测试段中，固定前 32 个的路由覆盖率为 12.87%，按历史热度固定 32 个为 39.65%；动态 LRU/EWMA 更高，但各需约 8 万次换入。单专家约 24 MiB 的主存到 NPU 搬运微基准，普通内存中位 3.661 ms，锁页内存中位 1.206 ms。

这组结果只证明所采请求的路由分布和独立搬运成本。请求数少、输出多在 96 token 上限截断；动态策略只做离线回放，未包含完整服务换入成本，也没有任何候选策略的端到端 decode 加速数据。它提供后续静态放置 A/B 的假设，尚不足以修改默认参数。

## 尚未取得的结果

2026-11-08 的[首轮单卡基线](2026-11-08-taishan-single-card-baseline/REVIEW.md)补上了现有配置下三种合成输入长度的客户端 TTFT、请求级 decode 速度、短时资源快照与正确性门槛：正式九次请求全部正常结束；TTFT 随输入长度显著增长，decode 速度在三组约 15.6 tok/s。该结果是短时顺序请求观察，不是持续吞吐或服务端 prefill 分项。

[双卡双实例对照](2026-11-08-taishan-dual-instance/REVIEW.md)用同一条 149-token、249-token 输出请求比较两条同时到达的服务容量。单实例排队三对的合计吞吐中位 13.55 tok/s；两张卡各一实例三对的合计吞吐中位 2.44 tok/s，降至 0.180 倍。所有输出一致，两卡图捕获路径可用；第二实例已停止，原服务健康。该负结果提示共享 CPU/内存或运行时资源争用，但没有细粒度数据确定根因，也不代表 TP/EP 性能。

[分层诊断](2026-11-08-taishan-dual-instance-diagnosis/REVIEW.md)补充了机制证据：第二实例仅加载时原实例保持约 15.57 tok/s，第二实例单独约 15.88 tok/s，只有两者同时执行才均降至约 1.25 tok/s；停止后原实例恢复约 15.69 tok/s。并发阶段 CPU PSI 约 90%，主机没有观察到活跃换页。KT 的绑核和自旋等待实现与 CPU 线程争用推断一致，但尚未通过改变线程预算的对照独立验证。

[第二实例 32 线程干预](2026-11-08-taishan-dual-instance-thread-budget/RESULT.md)形成了负结果：两实例并发时 CPU PSI 从 96+96 配置的约 90% 降至 96+32 配置的约 30%，但同协议的 128-token 合计吞吐只从 2.26 升到 2.35 tok/s，严重退化仍在。两次均只有一对正式并发请求，且跨日期、重启，3.9% 差异不构成稳定性能收益。两实例实际线程数为 158 和 94，尚需验证重叠绑核与 NUMA/内存带宽。热保护期间两卡最高 61°C/60°C，未复现高温故障，但高温根因尚未查明。双实例系列已[结项](2026-11-08-taishan-dual-instance-thread-budget/CLOSEOUT.md)，不继续排队实验。

仍没有服务端单独 prefill 时间和持续吞吐；没有单实例内部多请求执行、长上下文或 TP/EP 的正确性与性能验收；线程预算干预没有确认双实例退化的具体机制，也没有 NUMA 或专家放置参数的端到端配对收益；没有新版 SGLang 在这套 910B 环境下的回归结论。这些缺口的实验门槛见[研究计划](RESEARCH_PLAN.md)。
