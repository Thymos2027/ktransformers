更新：2026-11-10（北京时间）。本页依据已归档报告及只读服务器核查；服务状态会继续变化。执行顺序与验收口径见[研究计划](RESEARCH_PLAN.md)，成果边界见[阶段成果](RESEARCH_OUTCOMES.md)。

## 当前判断

当前主线是建立固定版本的 KT + SGLang 性能与正确性基线。[首轮顺序请求实验](2026-11-08-taishan-single-card-baseline/REVIEW.md)已完成并验收：三条正确性探针及九条正式请求通过，149/2066/6170 输入 token 的 TTFT 中位数分别为 2.469/28.609/83.844 秒，客户端生成速度约 15.6 tok/s。[双卡双实例系列](2026-11-08-taishan-dual-instance-thread-budget/CLOSEOUT.md)已结项：双实例同时执行显著退化；将第二实例 CPU 推理线程从 96 降至 32 后，并发 CPU PSI 约 90%→30%，同协议合计吞吐仅 2.26→2.35 tok/s，未获得稳定收益或具体代码修复依据。热保护未触发，第二实例已清理，原单卡服务健康。

## 下一次实验的完成条件

在新的日期目录中保存：实验前计划、环境与配置身份、固定请求集、正式轮逐请求结果、资源采样、错误与失败记录、结果汇总，以及服务恢复核查。只有通过正确性门槛的同配置请求才进入性能比较。若某场景因配置限制失败，应作为兼容性结果记录，不能以空白或短问答耗时补充性能表。

单卡首轮只运行客户端 API 请求与只读资源采样。双卡双实例对照、分层诊断和 32 线程干预已[结项](2026-11-08-taishan-dual-instance-thread-budget/CLOSEOUT.md)，原始证据与失败记录保留，不继续排队启动双实例实验。32 线程干预没有解决严重并发退化；实际 CPU 亲和性、NUMA 与内存带宽属于另立计划时再验证的假设。持续负载、服务端阶段计时、NUMA 单因素、长上下文和 TP/EP 仍未完成。
