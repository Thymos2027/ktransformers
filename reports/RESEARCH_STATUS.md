## 当前判断

下一步拟验证 TP2 正确性，见[本地方案](2026-11-12-taishan-tp-correctness/experiment-plan.md)。先固定 token 历史比较 logits 与关键层输出，区分 TP 与图模式影响，再做独立任务质量对照。尚未实现采集器、确定正式容差或启动服务器实验，不将计划计作通过结果。已有结果于 11 月 12 日[分享至 KT #2157](https://github.com/kvcache-ai/ktransformers/pull/2157#issuecomment-6810709188)。

用户要求的[TP=1/TP=2 速度对照](2026-11-11-taishan-tp-speed/REVIEW.md)已完成并验收：固定 32 常驻专家、96 CPU 线程、缓存上限 16384，同配置 ABBA 四次启动，144/792 输入各生成 512 token，共 24 条正式请求。TP2 的生成速度中位数高 3.37%/2.23%，请求总耗时少 2.87%/1.55%，TTFT 未改善。跨 TP 输出不同，因此仅为同输入同长度负载的小幅观察提升，没有数值等价或普遍加速承诺。原单卡服务恢复，16:26 独立核查健康正常；本轮不再排队启动新实验。

一个模型跨两张 NPU 的 TP=2/EP=1 已通过[第三轮短时功能验收](2026-11-10-taishan-tp2/REVIEW.md)：两卡 HCCL、eager 三条短请求、两 rank 的 decode 图捕获和图模式三条短请求均通过。必要配置为隔离候选显式放行 TP=2 及 `--max-total-tokens 16384`；每层 32 常驻专家、rank 0 唯一 CPU wrapper。该功能专项未测速度，后续速度对照见上一段；数值等价、长上下文与持续稳定性仍未验证。原单卡服务恢复及三条短请求通过，14:35 独立核查 `/health=200`、两卡 `OK`、53°C，TP 实验容器已停止。前两轮失败与全部原始证据保留。

当前主线是建立固定版本的 KT + SGLang 性能与正确性基线。[首轮顺序请求实验](2026-11-08-taishan-single-card-baseline/REVIEW.md)已完成并验收：三条正确性探针及九条正式请求通过，149/2066/6170 输入 token 的 TTFT 中位数分别为 2.469/28.609/83.844 秒，客户端生成速度约 15.6 tok/s。[双卡双实例系列](2026-11-08-taishan-dual-instance-thread-budget/CLOSEOUT.md)已结项：双实例同时执行显著退化；将第二实例 CPU 推理线程从 96 降至 32 后，并发 CPU PSI 约 90%→30%，同协议合计吞吐仅 2.26→2.35 tok/s，未获得稳定收益或具体代码修复依据。热保护未触发，第二实例已清理，原单卡服务健康。

## 下一次实验的完成条件

在新的日期目录中保存：实验前计划、环境与配置身份、固定请求集、正式轮逐请求结果、资源采样、错误与失败记录、结果汇总，以及服务恢复核查。只有通过正确性门槛的同配置请求才进入性能比较。若某场景因配置限制失败，应作为兼容性结果记录，不能以空白或短问答耗时补充性能表。

单卡首轮只运行客户端 API 请求与只读资源采样。双卡双实例对照、分层诊断和 32 线程干预已[结项](2026-11-08-taishan-dual-instance-thread-budget/CLOSEOUT.md)，原始证据与失败记录保留，不继续排队启动双实例实验。32 线程干预没有解决严重并发退化；实际 CPU 亲和性、NUMA 与内存带宽属于另立计划时再验证的假设。持续负载、服务端阶段计时、NUMA 单因素和长上下文仍未完成；固定专家集合的 TP 速度对照已单独验收。

TP=2 功能专项与固定专家集合的速度专项均已验收。下一轮如增加常驻专家、验证数值等价或扩大流量，应另立计划，不把现有短任务与同长度速度对照推广为完整质量或生产稳定性结论；当前不自动延伸新的后台实验。
